# 139Strm Pro

移动云盘（139 / 和彩云）专用的 **STRM 生成器 + 302 直链服务**，原生支持 `.cas` 秒传文件播放，**单个文件上限 500GB**。

它直连移动云盘官方接口，不经过 OpenList、不需要境外中转：

```
播放器 ──► 139Strm Pro (/d/xxx) ──302──► 移动云盘 CDN
                 │
            只做一次跳转
            视频流不经过服务器
```

> 本项目基于开源项目 [tianjian518/139strm](https://github.com/tianjian518/139strm) 重写：
> 协议层与 OpenList `drivers/139` 官方实现逐字节对齐（签名算法、Go 风格 JSON 序列化、AES 两层加解密），
> 界面与任务模型整体重做，并修掉了一批会直接导致「播放失败 / 配置丢失 / 还原风暴」的问题（见文末「相对原项目的改动」）。

## 一、核心能力

| 能力 | 说明 |
|---|---|
| **500GB 单文件** | 个人云接口使用 PC 客户端身份（`X-Yun-Client-Info` 客户端类型 `13`）。OpenList 上游注明：Web 端类型 `9` 单文件上限 50GB，PC 端类型 `13` 上限 **500GB** |
| **`.cas` 秒传播放** | 播放时按 SHA256 秒传还原成真文件再 302，不占空间、不耗上传流量 |
| **分片规则与官方一致** | >30GB 用 512MB 分片，否则 100MB；`/file/create` 按官方规则携带前 100 片 |
| **302 直连 / 代理可选** | 默认 302（视频流不经过服务器）；可切代理转发以消灭「直链 15 分钟过期」导致的中断 |
| **任务化同步** | 每个任务 = 一个云盘目录 + 增量/强同步 + 独立 crontab + 可强制终止 |
| **删除孤儿** | 云端删掉的影片，本地 `.strm` 跟着删（只删 `.strm`，绝不动字幕/图片） |
| **配置永不丢** | 原子写入 + 自动备份 + 损坏自恢复 + 坏文件隔离，读坏时自动从 `.bak` 恢复 |
| **单飞还原** | 同一部片子的并发播放请求串行处理，播放中反复换链只重签链接、不重复秒传 |
| **播放诊断** | 每次播放请求留痕（耗时、云盘往返次数、链接余命、是否续播），可跨重启保留 |

## 二、快速开始

### 方式一：Docker（推荐，AMD64 / ARM64 均可）

```bash
mkdir -p 139strm/{config,strm}
cd 139strm
# 把仓库里的 docker-compose.yml 拷过来，然后：
docker compose up -d --build
```

访问 `http://你的IP:8025`。

> ⚠️ **数据会不会丢，全看挂载**
>
> | 数据 | 容器路径 | 挂到宿主机（举例） |
> |---|---|---|
> | 配置 + 云盘凭据 + 任务列表 | `/app/config` | `/docker/139strm/config` |
> | 生成的 STRM | `/strm` | `/docker/139strm/strm` |
>
> 不挂载 = 数据只写在容器里，**容器一删就全没了**（升级版本通常就是重建容器）。
> 进「存储管理 → 💾 数据存储」可以确认两项是否都显示「✅ 已挂载/可写」。

### 方式二：直接运行

```bash
pip install -r requirements.txt
python app.py          # 默认端口 8025
```

Windows 下双击 `start.bat` 也可以直接启动。

### 方式三：Windows 本地跑 + Emby 同机

```bat
set PORT=8025
set CONFIG_PATH=%~dp0config\config.json
set YUN139_OUTPUT_DIR=%~dp0strm
python app.py
```

## 三、三步上手

### 第 1 步：配置移动云盘（左侧「存储管理」）

1. 用**无痕窗口**登录 <https://yun.139.com/>
2. `F12` → **网络（Network）** → 随便点开一个文件夹，触发一个请求
3. 点开任一请求 → **请求标头** → 找到 `Authorization`
4. 值是 `Basic xxxxxxxx...` 的形式 —— **去掉开头的 `Basic ` 和空格**，只留后面的 Base64

> 官方实现有硬校验：带了 `Basic` 前缀会直接报 `authorization should not include Basic prefix`。

**免抓包替代方案**：登录 <https://mail.10086.cn/> 后复制完整 Cookie（含 `Os_SSo_Sid` 与 `RMKEY`），
连同手机号一起填进「邮箱 Cookie」栏，令牌过期后程序会自动重新登录。

填好后点 **保存配置** → **测试连接**，看到账号 + 接入点 + 根目录条目数 + 凭据有效期即成功。

### 第 2 步：填「基础地址」（系统设置）

**基础地址**是写进每个 strm 的前缀，必须**播放器能访问到**：

- Emby 与 139Strm Pro 同机：`http://127.0.0.1:8025`（最稳）
- 局域网：`http://<宿主机私有 IP>:8025`
- ❌ 不要填 `172.17.0.x` 容器 IP、不要填公网 IP、本项目只跑 http

> 改了基础地址后，增量模式会自动发现内容变化并重写（不会漏更新）。

### 第 3 步：建任务（任务管理）

- **任务名**：`movie`（输出落在 `/strm/movie/…`，任务名就是壳目录）
- **扫描路径**：可用「存储浏览」进到目录后点「+ 在此目录新建任务」
- **同步模式**：增量（已有跳过，内容变了才重写）/ 强同步（全部覆盖）
- **同步删除**：勾上后云端删掉的影片，本地 `.strm` 同步删除
- **定时**：标准 crontab 五段表达式，留空 = 只手动跑

```
0 3 * * *       每天 03:00
*/30 * * * *    每 30 分钟
0 */6 * * *     每 6 小时
0 3 * * 1       每周一 03:00
```

任务表格点 **▶ 运行**，或右上 **▶ 运行所有**；运行中点 **⛔ 强制终止**，已生成的 strm 会保留。

## 四、接入 Emby / Jellyfin

1. 把 `./strm` 目录挂给 Emby（例如同样挂成 `/strm`）
2. 添加媒体库 → 类型「电影」或「电视剧」→ 路径选 `/strm`
3. 扫描入库（strm 只有几十字节，非常快）
4. 播放时 Emby 请求 strm 里的地址，本项目换取云盘直链后 302

### 生成的文件长什么样

| 云盘里的文件 | 本地文件 | strm 内容 |
|---|---|---|
| `VID_20220807.mp4` | `VID_20220807.mp4.strm` | `http://192.168.1.10:8025/d/Fk9se2Ip...` |
| `电影.mkv` | `电影.mkv.strm` | 同上 |
| `电影.mkv.cas` | `电影.mkv.strm` | 同上 + `?cas=电影.mkv.cas` |

`?cas=` 告诉服务端「这个文件要秒传还原」，普通文件不带这个参数。
（`?cas=` 后面的文件名**不做 percent-encode** —— 服务端要用它拼还原后的文件名，编码过的中文会变成一串 `%E7%94%B5`。）

## 五、`.cas` 秒传是怎么工作的

移动云盘里的 `.cas` 只有几百字节，内容是 Base64 的 JSON，记录着原始文件的名称、大小、MD5/SHA256。
真实数据早在云端，只是从文件列表里看不见了。

```
播放器请求 /d/xxx?cas=电影.mkv.cas
    │
    ├─ 1. 下载 .cas（几百字节），解出 SHA256 / 大小 / 原始文件名
    ├─ 2. 调 /file/create 做秒传 → 云端「凭空」还原出一个真文件（通常 1 秒左右）
    ├─ 3. 取这个临时文件的真实直链，302 给播放器
    └─ 4. 停止播放后延迟删除临时文件
```

- 临时文件放在个人云根目录的 `139STRM_TEMP`，同一部片子**始终只保留一份**；
- 播放中换链只对**同一个文件重签链接**，绝不删除播放器还在用的文件；
- 停止播放后按「临时文件最少保留秒数」延迟删除（默认 300 秒，实际不短于 30 分钟与直链余命）；
- 界面「秒传插件」页可以查看待清理数量，并一键清空残留。

### 关于 500GB

| 项 | 值 |
|---|---|
| Web 客户端（类型 9） | 单文件 50GB |
| **PC 客户端（类型 13，本项目默认）** | **单文件 500GB** |
| 分片 | >30GB 用 512MB/片，否则 100MB/片，与官方一致 |

> 500GB 是**协议层**的上限；实际能否还原还取决于账号权益。超出时接口会回「权益不足」，
> 本项目会把这句话翻译成人话提示，而不是抛一段原始报错。
> 如果某些环境对完整 PC 伪装头更友好，可在「存储管理」勾选「使用完整 PC 客户端伪装头」。

## 六、配置项

配置文件 `config/config.json`（可用环境变量 `CONFIG_PATH` 指定），也支持环境变量注入：

| 环境变量 | 说明 | 默认 |
|---|---|---|
| `PORT` | 服务端口 | `8025` |
| `CONFIG_PATH` | 配置文件路径 | `./config.json` |
| `YUN139_AUTHORIZATION` | 移动云盘凭据（优先级高于界面） | 空 |
| `YUN139_CLOUD_TYPE` | 云类型 | `personal_new` |
| `YUN139_OUTPUT_DIR` | STRM 输出根目录 | `/strm` |

| 界面项 | 说明 | 默认 |
|---|---|---|
| `client_type` | `pc`（500GB）/ `web`（50GB） | `pc` |
| `pc_full_headers` | 完整 PC 伪装头 | 关 |
| `cas_enabled` | 是否对 `.cas` 做秒传还原播放 | 开 |
| `cas_temp_ttl` | 临时文件最少保留秒数 | `300` |
| `cas_allow_all_ext` | 是否还原任意后缀（默认只还原视频） | 关 |
| `play_proxy` | 代理转发（流量经本机，可自动换链） | 关 |
| `media_ext` / `copy_ext` | 媒体 / 附属文件后缀 | 常见值 |
| `min_size_mb` | 小于此体积不生成 strm | `0` |

### 云类型

| 值 | 说明 |
|---|---|
| `personal_new` | **新版个人云（默认，也是唯一支持 CAS 秒传的类型）** |
| `personal` | 旧版个人云 |
| `family` | 家庭云 |
| `group` | 群组云（需填群组 ID） |

## 十、已知限制

1. **临时文件会短暂出现在云盘**：还原出来的文件会出现在根目录 `139STRM_TEMP` 里，停止播放后延迟删除。这是秒传还原的必要代价（OpenList 的 CAS 实现同样如此）。
2. **依赖云端源数据**：原始文件在云盘服务器上被彻底清理后，`.cas` 无法还原（提示「.cas 已失效」）。
3. **直链有有效期**：预签名直链实测约 15 分钟。本项目按直链自身过期时间缓存并留余量；若片长较长且播放器拿到链接后不回头，建议改用代理模式。
4. **凭据有效期**：Authorization 约 1~2 个月过期；剩余不足 15 天时自动续期，续期结果会写回配置；配置了邮箱 Cookie 还会自动重新登录。
5. **只有新版个人云支持 CAS**：`cloud_type` 必须是 `personal_new`。
6. **超大 CAS 受账号权益限制**：协议层上限 500GB，实际以账号会员权益为准。

## 十一、相对原项目（tianjian518/139strm 2.2.x）的改动

**协议 / 正确性**

- `sorted_json_stringify` 改为与 OpenList 完全一致：任意字符串先尝试按 JSON 解析（手机号会变成 `1.3800138e+10`），修复登录体加密与官方不一致的问题
- `calSign` 按 **UTF-8 字节**排序（原实现按码位排序，文件名含中文时签名与官方不一致）
- `encode_uri_component` 用 `safe="-_.~"`，与 Go `url.QueryEscape` 完全对齐
- AES-CBC 的 PKCS7 填充块长固定为 16（原实现在 AES-192 下用的是密钥长度）
- `X-Yun-Client-Info` 使用 PC 客户端类型 `13`（**500GB**），可切换完整 PC 伪装头

**稳定性 / 数据安全**

- 配置原子写入 + `.bak` 备份 + 损坏自恢复 + 坏文件隔离（原实现写坏即整份配置失效）
- `/api/config` 不再回显明文 Authorization / 邮箱 Cookie
- 播放路由的按片子串行锁原先直接返回裸 `Lock` 却被 `with` 使用，导致 CAS 播放必定抛 `TypeError`（已修）
- `.cas` 解析路径的 `requests.Session` 用法、响应体关闭等细节修正
- 目录列表翻页增加游标去重与页数上限（防接口异常时无限翻页）
- 秒传清理线程、临时文件删除增加失败重试记录与安全保护（不删播放器可能仍在用的文件）

**功能**

- 界面整体重做：左侧导航 + 任务表 + 目录选择器 + 秒传面板 + 播放诊断
- 增量模式改为「内容不一致才重写」，改基础地址后自动生效
- `.cas` 同名壳文件不再被当作字幕下载覆盖
- 任务删除可同时清理 strm；非法 crontab 在保存前校验并提示
- 新增 `start.bat`、端到端 mock 测试、完整的中文 README
